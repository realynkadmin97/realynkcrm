## Issues and solutions

**Vercel could not reach Supabase on the Direct host.** `db.*.supabase.co` returned ENOTFOUND from the deployment. Solution: use the Session pooler URI in `DATABASE_URL`, keep an optional direct URI in `DATABASE_URL_UNPOOLED` for migrations when available. Redeploy after each env save.

**Login worked, then the Harbor desk showed a generic server error.** Layout called `permissionsFor` → `withUser` → `SET ROLE crm_app`. On Supabase that often fails; a failed statement inside `BEGIN` aborted the whole transaction, so every desk query died. Production only showed Minified React error #441. Solution path: savepoints (`1037213`), then stop `SET ROLE` on the pool path entirely (`3cab108`). Pool queries run as `postgres` (owner bypasses RLS). Mutation routes still use `can()`. Layout permissions come from static `ROLE_PERMISSIONS` in `src/lib/permissions.ts`, not a DB round-trip.

**First browser kept showing #441 after the fix.** `/api/desk-check` while signed in returned `ok: true`, `role: admin`, `leadCount: 4`. Harbor opened in another browser. Solution: clear site data for `crm.realynk.com` on the stuck browser (or use the working one). Not a remaining server failure.
